# Selector recommendations

`/selector-tickets` shares the three reviewed Critical Phase Transition ticket pools from `data/event-announcements.json`, official pack art, the event ticket dialog and nested operator preview. Recommendation badges are opt-in and appear only on this guide.

The scoring function is `lib/selectors/scoring.ts`. It uses the shown imported account's operator names from the existing local account store; planner goals are not ownership. No account means base scores without roster bonuses. Owned candidates retain their scores and show an Owned marker. Ticket dialogs sort by the displayed total from highest to lowest, including account bonuses, with alphabetical ties. A changed account recalculates the order. Event dialogs without recommendation scores retain their original order.

The user-supplied sheet is `config/selector-ratings.csv`; Ling is corrected to 6.7 as requested. Run `npm run selectors:ratings` after updating it to resolve the reviewed spelling aliases and write `data/selector-ratings.json`, keyed by game character ID (the record; publish it from arkpedia-data). Blank cells stay unrated; unknown names, duplicate IDs and invalid scores fail the import. They must be reviewed Kukkikaze ratings. When only one usable rating exists, double its rating points, whether it is Kukkikaze or community: −1 becomes −2, 0 stays 0, +1 becomes +2, and +2 becomes +4. Skill/module/roster bonuses are added afterward. Neither rating means an available subtotal identified in the accessible breakdown. Badges use signed point totals with no asterisk, colored red below zero, yellow below five and green at five or more. A Game-Destroyer bonus also stays pending if an owned operator's author rating is unknown. Community averages come from the published Power Scale poll and round to the nearest tenth. Each rating contributes `(rounded tenths - 63) * 0.25`: 5.8 gives -1.25, 6.3 gives 0, 6.7 gives +1, 7.1 gives +2, and 7.2 gives +2.25.

Skill priorities count unique skills, using main over sub if a skill has several mastery entries. Each main priority skill adds +0.5; sub priority skills add 0 by default, optionally +0.1 each. ISW and RA module prefixes each contribute once. Base talents that reveal Invisible enemies or make enemies lose Invisibility contribute +0.25 once per operator when reveal coverage is enabled; skills, modules, and talents that grant allied Invisibility do not qualify. The +0.5 Arts coverage bonus counts owned six-star Casters and Supporters together, and applies with three or fewer in that combined group. Direct Arts/True damage descriptions in traits, skills and talents supply the coverage classifications, including summons; damage-taken mentions alone do not classify a dealer. If the product needs a narrower definition of damage dealer, add reviewed ID overrides instead of replacing this with class heuristics.

Color defaults are negative below 0, middle 0–under 5, great 5+. All numeric quarter-point contributions are retained. The rules disclosure and portrait accessible names expose the breakdown.

`build-selector-catalogue.ts` regenerates the compact projection during predev and prebuild, The content page export calls the catalogue builder directly against its hydrated source records. The content exporter publishes `/selector-tickets` as versioned page props, so subsequent data releases update it without a frontend deployment. The generated JSON is also a bundled fallback for ISR while a newly deployed route is absent from the older release. Production promotion remains separate from development preview.

## Personalization

Each selector popup offers Personalize recommendations. Its settings replace the operator grid within the same modal, preserve its geometry, and return to the previous list scroll position. Escape from settings returns to the list and restores focus to the personalization button; another Escape closes the ticket. Fixed Kukkikaze/community rating weights and the +0.5 main-skill weight are read-only. See scoring expands the complete nearest-tenth scale. Sub skills are off by default and add +0.1 each when enabled.

The Arts and True coverage bonuses are +0.5, super-meta coverage is +1 for a Kukkikaze rating of 7.0+ or an operator in `config/selector-super-meta.json`, and talent-based reveal is +0.25 without stacking another reveal contribution. Account defaults use three or fewer owned six-star Casters/Supporters combined for Arts; no owned six-star True damage dealer, super-meta operator, or talent-reveal operator for the other respective coverage bonuses. Unrated owned operators leave automatic super-meta coverage unknown unless another owned operator already establishes coverage. Manual Yes/No answers override account defaults, including without an import. Without an account, reveal starts on and the other coverage bonuses start off. IS/RA modules retain their existing +0.5 each.

Preferences live in this browser under `arkpediaSelectorPreferences:<server>` (or `:manual` without an account), version 1. Null coverage fields follow future account imports; explicit booleans remain manual overrides. The account-default action restores automatic coverage and turns sub skills off. Friend imports never supply ownership. Point totals round to two decimals so optional +0.1 bonuses do not expose floating-point artifacts.

The explicit super-meta list includes Ines, Ela, Lemuen, Eyjafjalla the Hvít Aska, Ascalon, Lappland the Decadenza, Logos, Yu, Ulpianus, Exusiai the New Covenant, Wiš'adel and Tragodia. Stable operator IDs distinguish alter forms from the originals. The same classification controls the candidate bonus and owned-roster coverage; author ratings are unchanged. Changes to this app configuration require a dev deployment.
